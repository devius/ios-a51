# A51 GPU sub-project 2: Mesa Panfrost in iOS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `osmesa-test` on the A51 draws a pixel-checked triangle with OpenGL through Mesa's Panfrost on the Mali-G72 and prints fps, next to softpipe's fps.

**Architecture:** The S7 port's `gpu/mesa/` (Mesa 25.0.7 OSMesa + Gallium Panfrost, libdrm stand-in `herodrm.c` over the kernel's `HeroGPU`), renamed for the A51 and installed under `/private/var/a51gpu`, cross-built on the Mac VM and run over SSH.

**Tech Stack:** Mesa 25.0.7, libdrm 2.4.124 headers, meson/ninja, Xcode 15.2 iphoneos SDK (arm64, iOS 16.0 min), ad-hoc codesign; Python 3 for the patcher.

**Spec:** `docs/superpowers/specs/2026-10-29-a51-gpu-mesa-design.md`

## Global Constraints

- Mesa tag `mesa-25.0.7` (`081368f8…`), libdrm tag `libdrm-2.4.124` (`34e9eed6…`).
- Install paths on the phone: dylibs `/private/var/a51gpu/lib`, test `/private/var/a51gpu/osmesa-test`; rpath `/private/var/a51gpu/lib`.
- Nothing of Apple's committed or in artifacts; SDK only at build time on the Mac VM.
- No root-image change; everything over SSH (`ssh -i build/ssh/a51_ed25519 -o UserKnownHostsFile=build/ssh/known_hosts root@192.168.7.2`).
- Start on the running boot 42 (kernel143). Any boot write (kernel144, a 0145 job-limit patch) needs the owner's approval first.
- A GPU result counts only if `GL_RENDERER` names Panfrost / Mali-G72; softpipe is never reported as GPU.
- `HERODRM_HEAP_MB` default 32.

## Review Focus

1. **Silent softpipe fallback** (`hero_hw_create_screen` returns NULL, OSMesa uses softpipe): `osmesa-test` must fail when `GL_RENDERER` is not Panfrost (Task 2 check).
2. **A job fault or 200 ms timeout** on the first real Bifrost job: visible in the kernel log (`A51 GPU: job … status`), test exits non-zero; handled in Task 4's branches.
3. **Patcher drift:** `patch-mesa.py` must fail loudly on an unexpected Mesa tree (it asserts single matches); Task 1 runs it on a clean 25.0.7 checkout.
4. **Wrong install names:** a dylib still pointing at the build tree or `/usr/local` fails to load on the phone; Task 3 checks every `otool -L` line.
5. **Stale stand-in description:** `herodrm.c` must not claim "Mali-T880 (Galaxy S7)" in the version string Mesa logs (Task 1 grep).
